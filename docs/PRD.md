## 1. 产品概述

### 1.1 一句话定位
一个基于 **多 Agent 协作** 的智能调研与知识库助手：用户输入一个调研主题或上传私有文档，系统自动调度多个 AI Agent 完成「任务拆解 → 知识库检索 → 联网搜索 → 数据分析 → 报告撰写 → 邮件发送」全流程，过程流式透明可见。

### 1.2 目标用户与场景
| 用户 | 核心场景 |
|------|----------|
| 调研人员 / 分析师 | 输入主题，一键产出结构化调研报告 |
| 知识工作者 | 上传私有文档（PDF/Word/Excel…），基于文档内容问答 |
| 个人 / 小团队 | 用自然语言驱动工具链，无需学习复杂工具 |

### 1.3 产品目标
1. **降本增效**：把「检索 → 搜索 → 分析 → 写报告 → 发邮件」的人工流程压缩为一句自然语言。
2. **私有知识利用**：RAG 让模型回答基于用户自有文档，而非仅凭训练数据。
3. **过程透明**：Agent 的每一步工作状态实时流式展示，用户可信任结果来源。
4. **沉浸体验**：去侧边栏的悬浮指挥中心布局 + 玻璃拟态 + 暗黑模式，符合 2025 AI 产品主流视觉。

### 1.4 非目标（本期明确不做）
- 不做多用户账号体系与权限（后端正规划多租户演进，本期为单用户）。
- 不做支付 / 计费 / 用量配额。
- 不接入移动端原生 App（本期仅 Web 响应式起步）。

## 2. 技术架构

```
┌────────────────────────── 前端 Next.js 16 (Vercel) ──────────────────────────┐
│  App Router 5 路由   Tailwind CSS 4    AI SDK v6 (useChat)   ReactMarkdown   │
└───────────────┬──────────────────────────────────────────────────────────────┘
                │ fetch / SSE（UI Message Stream: text-start → text-delta → text-end）
┌───────────────▼────────────────────────────────────────── 后端 FastAPI (Fly.io) ─┐
│  /chat        主 Agent ReAct 循环 + Function Calling（最大 5 轮）                 │
│                 ├─ 知识库检索员 → Chroma 向量检索（LangChain + BGE-M3 + 检索词扩展）│
│                 ├─ 联网搜索员   → Tavily Search API                               │
│                 ├─ 数据分析师   → 结构化整理                                      │
│                 ├─ 报告撰写师   → Markdown 报告落盘 reports/ + 转 HTML            │
│                 └─ 邮件发送员   → SMTP（正文 + HTML/MD 附件）                     │
│  /upload_file  /knowledge  /reports  /history  /ping                             │
│  SQLite（对话历史）  Chroma（向量库）  本地文件（uploads/ reports/）               │
└───────────────────────────────────────────────────────────────────────────────────┘
  模型: DeepSeek (deepseek-chat)   嵌入: BGE-M3 (硅基流动)
```

### 关键决策
- **手写 ReAct + Function Calling**，不依赖 LangChain Agent 框架，流程可控、易调试。
- **前后端分离**：AI 逻辑全部在 Python 后端；前端仅负责渲染与 API 调用。
- **流式协议**：后端 SSE 兼容 AI SDK v6 UI Message Stream，前端零侵入接入 `useChat`。

## 4. 非功能需求（NFR）

| 编号 | 类别 | 需求 |
|------|------|------|
| NFR-01 | 性能 | 对话采用流式输出，首 token 尽量快；知识库检索 Top-K 合并去重后最多 3 条，控制上下文体积 |
| NFR-02 | 稳定性 | Agent 循环设最大 5 轮上限，防止死循环；工具 JSON 解析失败有兜底（空对象） |
| NFR-03 | 安全 | API Key（DeepSeek / SiliconFlow / Tavily / SMTP）存环境变量或 secrets，不上传 Git；CORS 仅允许白名单来源 |
| NFR-04 | 可靠性 | 上传格式白名单校验；不支持的格式明确报错 |
| NFR-05 | 可扩展性 | SQLite → PostgreSQL 迁移规划中；Chroma 持久化支持向量库升级；后端向 SaaS 多租户演进 |
| NFR-06 | 可访问性 | 全站支持暗黑模式；字体使用系统栈，无外部字体依赖（Google Fonts 不可达时的稳健选择） |
