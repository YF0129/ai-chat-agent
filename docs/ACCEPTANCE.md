# 验收标准（Acceptance Criteria）— Multi-Agent 智能调研与知识库助手

> 配套文档：[产品需求文档](./PRD.md)
> 版本：v1.0（2026-08-16）
> 说明：每条验收标准对应 PRD 功能编号（M0–M6 / NFR），编号可追踪。勾选标记：✅ 当前已满足 / ⬜ 未实现，须在对应里程碑验收。

---

## 0. 验收总则

1. **范围**：验收覆盖 PRD 中 M0–M6 全部功能需求与非功能需求（NFR）。
2. **环境**：验收在本地（前端 `npm run dev` + 后端 `uvicorn main`）与线上（Vercel + Fly.io）双环境执行；后端需配置 `DEEPSEEK_API_KEY`、`SILICONFLOW_API_KEY`（BGE-M3）、`TAVILY_API_KEY`、`SMTP_*`。
3. **通过条件**：每条验收标准均可独立判定「通过 / 不通过」；P0 级别（核心链路）有一条不通过即整体不通过，P1 级别允许标注缺陷并排期修复后复验。
4. **判定方法**：功能类标准按「操作步骤 → 预期结果」验证；视觉类标准以设计规范为准进行目测对比；性能类标准以实测数据为准。

## 10. 复验与回归建议

1. **核心链路回归（P0）**：每次发布前跑一遍「上传文档 → 基于文档问答 → 联网搜索 → 生成报告 → 发邮件」全链路，任何一步失败即阻断发版。
2. **暗黑模式回归**：新增页面/组件时，需在亮暗两种模式下各检查一遍玻璃拟态与对比度。
3. **数据联动回归**：验证「删除知识库文件 → 清空对话历史」联动；「生成报告 → 报告中心可见」联动。
4. **验收顺序**：按 M0 → M2 → M3 → M1 的顺序（先基础框架，再数据管理，最后复杂 Agent 链路），便于尽早暴露依赖问题。
